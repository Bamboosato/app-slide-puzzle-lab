# App Slide Puzzle Lab レビュー指摘対応・実装指示書

## 1. 対象

- リポジトリ: `Bamboosato/app-slide-puzzle-lab`
- 対象ブランチ: `main`
- レビュー基準コミット: `cce2900a3aba89808a920ed0606e0b0b6fd540f7`
- 対象要件: `docs/app-slide-puzzle-lab-requirements-v1.0.md`

## 2. 目的

現状の主要機能とUIを維持しながら、以下を改善する。

1. ポーズ・モーダル表示中の背後操作を完全に禁止する。
2. 「軽め・標準・強め」のシャッフル差を実際の盤面に反映する。
3. シャッフル失敗時にも極端に簡単な盤面を返さない。
4. 画像分割時に右端・下端の画素が欠けないようにする。
5. モーダルのキーボード操作とフォーカス制御を改善する。
6. 回帰防止テストとCIを追加する。

## 3. 実装時の共通方針

- 現在の画面デザイン、画面遷移、PWA機能を不要に変更しない。
- パズルロジックとUIの分離を維持する。
- タップ、クリック、スワイプ、キーボードの全操作経路で同じ操作可否判定を使用する。
- 既存の設定保存キーを変更しない。
- 既存テストを削除または弱体化してテストを通さない。
- 変更に対応する単体テストまたはコンポーネントテストを追加する。
- 要件定義の記述を変更する場合は、実装上の都合ではなく確定した仕様として整合させる。

## 4. 対応項目

## P0-1 ポーズ・モーダル表示中の操作禁止

### 問題

`usePuzzleGame`がグローバルな`keydown`イベントを常時処理しているため、以下の状態でも矢印キーによって盤面が動く可能性がある。

- 手動ポーズ中
- 元画像モーダル表示中
- 確認ダイアログ表示中
- 完成ダイアログ表示中

この場合、タイマーが停止した状態で手数と盤面だけが進み、記録の整合性が崩れる。

### 主な対象ファイル

- `src/hooks/usePuzzleGame.ts`
- `src/components/puzzle-play/PuzzlePlayScreen.tsx`
- `src/components/puzzle-play/PuzzleBoard.tsx`
- 必要に応じて`src/components/puzzle-play/PuzzlePiece.tsx`

### 実装方針

1. `PuzzlePlayScreen`で、操作禁止状態を一元的に算出する。

```ts
const isInteractionDisabled =
  isManualPaused ||
  showOriginalModal ||
  confirmAction !== null ||
  isCompletionDialogOpen ||
  isCompleted;
```

2. `usePuzzleGame`に`isInteractionDisabled`を渡せるようにする。
3. `moveByTileIndex`、`handlePieceSwipe`、`handleKeyDown`の先頭で同じ状態を確認し、禁止中は何もしない。
4. `PuzzleBoard`にも状態を渡し、禁止中は全ピースを操作不可として表示する。
5. UI側で無効化していても、ゲームロジック側のガードを必ず残す。
6. ダイアログを閉じる、またはポーズを解除した後は、正常に操作を再開できること。

### 補足

- `isInteractionDisabled`がコールバック内で古い値にならないよう、依存配列または`ref`を適切に管理する。
- キーボードイベントを登録解除する方式でもよいが、タップやスワイプと判定が分散しない設計を優先する。
- 矢印キー以外の操作やモーダル内のTab移動を妨げないこと。

### 受入条件

- ポーズ中にタップ、クリック、スワイプ、矢印キーを操作しても盤面と手数が変化しない。
- 元画像モーダル、確認ダイアログ、完成ダイアログ表示中も盤面と手数が変化しない。
- タイマー停止中に隠れて手数だけ増える状態が発生しない。
- ポーズ解除またはモーダルを閉じた後は、再び正常に操作できる。
- 完成後は、ダイアログを閉じても盤面を操作できない。

## P0-2 シャッフル難易度の評価条件をレベル別にする

### 問題

現在はすべてのシャッフルレベルに対して「正解位置にあるマスが全体の50%以下」という同一条件を適用している。そのため、「軽め＝完成状態に近い」という画面説明と生成される盤面が一致しにくく、難易度差も弱くなる。

### 主な対象ファイル

- `src/config/constants.ts`
- `src/logic/puzzleLogic.ts`
- `src/logic/puzzleLogic.test.ts`
- `docs/app-slide-puzzle-lab-requirements-v1.0.md`

### 実装方針

シャッフル手数に加えて、レベル別の盤面評価条件を定数として一元管理する。

初期案は以下とする。

| レベル | 合法手数 | 正解位置に残るマス数の目安 |
| --- | ---: | ---: |
| 軽め | 総マス数×3 | 全体の50～80%程度 |
| 標準 | 総マス数×10 | 全体の20～50%程度 |
| 強め | 総マス数×30 | 全体の0～35%程度 |

実装上は、少なくとも上限値をレベル別にする。

```ts
export const MAX_SOLVED_TILE_RATIOS: Record<ShuffleLevel, number> = {
  light: 0.8,
  standard: 0.5,
  hard: 0.35,
};
```

「軽め」に下限値を設けるかは任意とする。下限を設ける場合は、生成失敗率と処理時間を確認すること。

### 注意事項

- 正解位置数は最短手数ではないため、難易度の近似値として扱う。
- 空白マスを正解位置数に含めるか除外するかを実装とテストで統一する。
- UI文言と要件定義を、実際の判定方法に合わせる。
- 「数学的に難易度を保証する」など、正解位置数だけでは裏付けられない表現は使用しない。

### 受入条件

- 軽め、標準、強めで異なる盤面評価条件が使用される。
- すべての生成盤面が合法手だけで生成され、完成可能である。
- 生成直後に完成状態にならない。
- 各レベルの生成条件が定数として一元管理されている。
- 全分割数と全シャッフルレベルの組み合わせをテストできる。

## P0-3 シャッフルのフォールバック改善

### 問題

指定回数の試行で条件を満たさない場合、現在は完成状態から1手だけ移動した盤面を返している。このため、「強め」を選択しても1手で完成する盤面が返る可能性があり、レベル別の条件も保証されない。

### 主な対象ファイル

- `src/logic/puzzleLogic.ts`
- `src/logic/puzzleLogic.test.ts`

### 実装方針

以下のいずれかで対応する。推奨は方式Aとする。

#### 方式A：試行中の最良盤面を返す

- 各試行で得られた盤面を評価する。
- 完成状態ではない盤面のうち、対象レベルの条件に最も近い盤面を保持する。
- 上限試行回数に達した場合は、1手盤面ではなく最良盤面を返す。

#### 方式B：追加シャッフルする

- 上限試行回数後も完成状態から1手には戻さない。
- 最後の盤面から合法手による追加シャッフルを実行し、最低限の崩れ条件を満たすまで継続する。
- 無限ループ防止の絶対上限を設ける。

### 実装上の必須条件

- フォールバックで完成状態を返さない。
- フォールバックで1手だけの盤面を返さない。
- 返却配列に`0`から`N²-1`までが重複なく1つずつ存在する。
- 生成過程は合法手のみとし、完成可能性を維持する。
- テストで乱数を固定またはモックし、フォールバック経路を確実に通す。

### 受入条件

- `Math.random`を意図的に偏らせても、1手で完成するフォールバック盤面を返さない。
- フォールバック経路のテストが偶然性に依存せず再現可能である。
- 全レベル・全分割数で配列の完全性と非完成状態が保証される。

## P1-1 画像分割時の端数処理

### 問題

`Math.floor(squareCanvas.width / gridSize)`で全ピースを同じ整数幅にしているため、1024pxを3、5、6で割った余りが右端・下端から欠落する。

| 分割数 | 現在の使用幅 | 欠落 |
| --- | ---: | ---: |
| 3×3 | 341×3＝1023px | 1px |
| 5×5 | 204×5＝1020px | 4px |
| 6×6 | 170×6＝1020px | 4px |

### 主な対象ファイル

- `src/logic/imageProcessor.ts`
- 新規または既存の画像処理テストファイル

### 実装方針

各ピースの境界座標を比率から個別に算出する。

```ts
const x1 = Math.round((col * width) / gridSize);
const x2 = Math.round(((col + 1) * width) / gridSize);
const y1 = Math.round((row * height) / gridSize);
const y2 = Math.round(((row + 1) * height) / gridSize);

const tileWidth = x2 - x1;
const tileHeight = y2 - y1;
```

ピースごとの幅・高さは最大1px異なってよい。元画像の全領域を重複・欠落なく使用することを優先する。

### 受入条件

- 3×3、4×4、5×5、6×6のすべてで元画像の右端と下端まで使用される。
- 分割領域に隙間または重複がない。
- 生成されるピース数が常に`gridSize²`である。
- 既存の盤面表示サイズとレイアウトが崩れない。
- 元画像と完成時のピース画像に明らかな端欠けがない。

## P1-2 モーダルのアクセシビリティ改善

### 問題

現在の共通モーダルには、次の不足がある。

- 開いたときの初期フォーカス設定
- モーダル内へのフォーカストラップ
- 閉じたときの呼び出し元へのフォーカス復帰
- `ConfirmDialog`の見出しと`aria-labelledby`の関連付け
- 背景コンテンツへのキーボード操作抑止

### 主な対象ファイル

- `src/components/common/Modal.tsx`
- `src/components/common/ConfirmDialog.tsx`
- `src/components/puzzle-play/OriginalImageModal.tsx`
- `src/components/puzzle-play/CompletionDialog.tsx`

### 実装方針

1. モーダルを開く直前の`document.activeElement`を保持する。
2. 開いた直後に、閉じるボタン、キャンセルボタン、または最初の操作可能要素へフォーカスする。
3. Tab／Shift+Tabをモーダル内で循環させる。
4. 閉じたときは、存在していれば呼び出し元へフォーカスを戻す。
5. 各モーダルに一意の見出しIDを付け、`aria-labelledby`で関連付ける。
6. 見出しがない場合は`aria-label`を必須とする。
7. Escapeで閉じてよいモーダルと、確認を要求するモーダルの仕様を維持する。

`useId()`を利用し、複数モーダル間で固定IDが重複しないようにする。

### 受入条件

- モーダル表示直後にフォーカスがモーダル内へ移る。
- Tabキーで背景のボタンへフォーカスが移らない。
- Escapeまたは閉じる操作後、フォーカスが呼び出し元へ戻る。
- すべての`role="dialog"`にアクセシブル名称がある。
- マウス、タッチ、キーボードの既存操作を維持する。

## P1-3 タッチ操作の二重実行防止

### 問題

`PuzzlePiece`は`touchend`内で短い移動をタップとして`onClick()`へ渡し、同時にボタンの`onClick`も登録している。ブラウザによってはタッチ後の合成クリックが発生し、同一操作が二重処理される可能性がある。

### 主な対象ファイル

- `src/components/puzzle-play/PuzzlePiece.tsx`
- 必要に応じて`src/hooks/useSwipe.ts`

### 実装方針

Pointer Eventsへの統一を優先する。

- `pointerdown`で開始座標と`pointerId`を記録する。
- `pointerup`で移動量を判定する。
- 閾値未満は通常のクリック経路に任せるか、手動実行する場合は直後のclickを抑止する。
- 閾値以上はスワイプとして1回だけ処理する。
- `pointercancel`で状態を破棄する。
- マウスクリック、タッチ、ペン入力を維持する。

既存のTouch Eventsを維持する場合は、スワイプ後の合成clickを明示的に抑止し、タップが1回だけ処理されることをテストする。

### 受入条件

- 1回のタップで手数が1だけ増える。
- 1回のスワイプで手数が1だけ増える。
- スワイプ後に追加のクリック移動が発生しない。
- 無効な方向へのスワイプでは盤面と手数が変わらない。

## P2-1 テスト拡充

### 追加するテスト

#### パズルロジック

- 3×3～6×6と軽め～強めの全12組み合わせ
- 完成状態でないこと
- 盤面要素の重複・欠落がないこと
- レベル別評価条件を満たすこと
- 乱数を固定したフォールバック経路
- 直前手の即時逆戻りを候補から除外すること

#### 操作状態

- 通常プレイ中はタップ、スワイプ、矢印キーで移動できる
- ポーズ中は全操作経路が無効
- 元画像モーダル中は全操作経路が無効
- 確認ダイアログ中は全操作経路が無効
- 完成後は全操作経路が無効
- 各状態を解除すると操作が再開する

#### タイマー

- ゲーム開始、停止、リセット
- 元画像表示中の停止と復帰
- 手動ポーズと復帰
- `visibilitychange`による自動ポーズ
- 完成時の即時停止
- ポーズ中の操作では経過時間・手数とも変化しない

#### 画像処理

- 3×3、4×4、5×5、6×6の分割数
- 全領域を欠落・重複なく分割すること
- JPEG、PNG、WebPの形式判定
- 透過画像の白背景合成
- 1024pxを超える画像の縮小

#### モーダル

- 初期フォーカス
- Tab／Shift+Tabの循環
- Escapeによるクローズ
- 閉じた後のフォーカス復帰
- アクセシブル名称

### テスト方針

- 乱数依存テストは`Math.random`をモックし、再現可能にする。
- 時間依存テストはfake timerを使用する。
- Canvas APIは必要最小限のモックを用意し、座標計算を独立関数へ切り出して検証する。
- 実装詳細ではなく、利用者から見た振る舞いと不変条件を検証する。

## P2-2 GitHub ActionsによるCI追加

### 新規対象ファイル

- `.github/workflows/ci.yml`

### 必須処理

Pull Requestおよび`main`へのpushで、以下を実行する。

```bash
npm ci
npm run test:run
npm run build
```

### 推奨設定

- Node.jsはプロジェクトで正式採用するLTSバージョンに固定する。
- npmキャッシュを有効にする。
- ジョブにタイムアウトを設定する。
- テストまたはビルド失敗時はワークフローを失敗させる。

### 受入条件

- Pull Request作成時に自動実行される。
- 単体テスト失敗時にCIが失敗する。
- TypeScriptエラーまたはViteビルド失敗時にCIが失敗する。
- 正常時に`npm run test:run`と`npm run build`の両方が成功する。
