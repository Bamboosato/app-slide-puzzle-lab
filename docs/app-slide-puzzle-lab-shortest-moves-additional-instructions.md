# App Slide Puzzle Lab 最短手数表示・追加実装指示書

作成日：2026-09-24  
対象：`Bamboosato/app-slide-puzzle-lab` の現行実装  
位置付け：既存要件とレビュー指摘対応に対する追加要件。既存要件の「最短手数の算出はMVP対象外」を、この機能について更新する。

## 1. 目的と確定した仕様

プレイ開始時の盤面から完成するまでの最短手数を、パズル画面で簡潔に示す。プレイヤーは計算を待たずに遊び始められるようにする。

- **1手**は、空白マスに上下左右で隣接するピースを、空白へ1マス移動すること。シャッフル、探索、プレイヤーの手数を同じ規則で扱う。複数ピースの一括移動は対象外。
- 最短手数の計算対象は、**シャッフル完了時に確定した初期配置**。プレイ中に変化する現在の盤面を毎手解き直さない。
- 3×3・4×4では厳密な最短手数を試算する。探索の暫定上限は、開始要求から**3,000 ms**。これは正式な性能保証値ではなく、計測して調整するための初期設定値。
- 3秒以内に厳密解を確定できなければ、空白を除く各ピースの**マンハッタン距離の合計**を下限として表示する。完成状態と各ピースの正解位置は、ゲーム本体と同じ定義を用いる。
- 5×5・6×6は今回、厳密探索の対象外とし、初期配置のマンハッタン距離による下限をすぐ表示する。サイズが大きい盤面で不要な3秒間の探索を走らせない。
- 画像や盤面を外部へ送らない。計算と必要なコード・データは、既存PWAのオフライン利用でも機能させる。

## 2. 表示仕様

パズル画面の手数・経過時間の近くに、次の表示を追加する。技術用語や説明文を常時表示する必要はない。

| 状態 | 表示例 |
| --- | --- |
| 3×3・4×4、探索中 | `最短 計算中…` |
| 厳密解が確定 | `最短 42手（0.5秒）` |
| 3秒で探索終了 | `最短 32手以上（3.0秒）` |
| 5×5・6×6、下限のみ | `最短 32手以上` |

- `以上`のない数値だけを厳密な最短手数として扱う。マンハッタン距離を確定値として表示しない。
- 括弧内は最短手数の探索要求から結果または打ち切りまでの**実測経過時間**であり、プレイ時間ではない。小数第1位の秒数に統一する。タイムアウト時は実測値を表示し、タイマーの誤差で3.0秒を多少超えても、実測を偽って3.0秒に固定しない。
- 探索を試みない5×5・6×6には、意味の薄い`0.0秒`を表示しない。
- 完成ダイアログへ結果を載せる場合も、同じ意味と表記を使う。結果が未確定のまま先に完成しても、プレイの完了を妨げない。
- 既存のプレイヤーの「手数」「経過時間」表示は維持し、最短手数と取り違えない配置にする。

## 3. 実装方針

### 3.1 探索と操作の分離

1. シャッフル完了時に、初期配置の**不変なスナップショット**を保持し、マンハッタン距離を即時に計算する。
2. 3×3・4×4では、そのスナップショットをWeb Workerに渡して厳密探索を開始する。探索をUIスレッドで同期実行しない。
3. 3×3はBFSまたはA*など、4×4はIDA*などを選択する。厳密値を返すには、探索の完了まで最適性を保証できる手法と過大評価しないヒューリスティックを使う。必要なら線形コンフリクトやパターンデータベースを検討するが、正しさと端末での実測を優先する。
4. Workerが期限内に確定値を返したら表示を更新する。期限を超えたらWorkerを停止し、保持してあるマンハッタン距離を下限として表示する。Workerがエラーになった場合もプレイを継続し、下限へ切り替える。
5. Wasmは採用を必須としない。JS実装を含め実機の計測結果に基づいて選択する。Wasmや探索用データを採用した場合はローカル配信・オフラインキャッシュに含める。共有メモリやマルチスレッドを前提にしない。

### 3.2 盤面と計算のライフサイクル

- プレイヤーの移動中も、探索対象は初期配置のまま。移動ごとに探索を再起動しない。
- **最初から**：初期配置が同一なので、その盤面に対する結果または進行中の探索を再利用する。
- **再シャッフル／新しい画像／分割数の変更／画面離脱**：古い探索を停止または破棄し、新しい盤面の結果と混ざらないようにする。非同期応答には盤面IDなどを対応付け、遅れて返った旧盤面の結果を無視する。
- 同時に複数の重い探索を走らせない。画面離脱時はタイマーとWorkerを解放する。
- 計算中もタップ、スワイプ、キーボード操作、ポーズ、元画像表示、完成判定、やり直しを従来どおり動作させる。既存のポーズ・モーダル中の操作禁止仕様は守る。
- 3,000 msの設定値を一箇所に定義する。Workerの開始遅延も含む画面側の経過時間と打ち切り判定を一貫させる。

## 4. テスト・受入条件

1. 1手・2手で解ける既知の盤面、3×3の難しい既知盤面、4×4の既知盤面で、厳密値と実際の合法手順が一致する。最適性の根拠がない単一のシャッフル履歴の長さを期待値にしない。
2. マンハッタン距離は空白を加算せず、複数の既知盤面で厳密最短手数以下となる。表示が下限の場合は必ず`以上`が付く。
3. タイムアウトを制御したテストで、3,000 ms後に下限表示へ切り替わり、処理が止まり、後着の結果で表示が上書きされない。
4. Workerエラー、途中の再シャッフル、最初から、画面離脱、連続した新規パズルで、旧盤面の結果が混入しない。
5. 探索中でも実際にピースを動かせる。手数・タイマー・盤面・完成判定は探索結果に依存しない。ポーズやモーダル中に操作できない既存動作も維持する。
6. 5×5・6×6は探索待ちなしで`以上`表示になる。3×3・4×4もタイムアウトやエラーによってプレイ開始が妨げられない。
7. PCとスマートフォンで、通常のシャッフルおよび難しい盤面について、確定率と計算時間を記録する。上限3秒の妥当性はその結果で判断し、全盤面で1秒以内などの未検証の保証をしない。
8. オフライン起動後も計算表示が機能し、画像や盤面のネットワーク送信がない。既存のテストと本番ビルドも成功する。
